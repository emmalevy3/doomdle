# Doomdle

A daily Wordle-style Magic: The Gathering puzzle. The player sees a game state (hand, board, mana, life, library/graveyard, an open-information opponent) and must build a Doomsday pile that wins this turn. This repo is the Rust rules engine and solver that validates submitted piles. It will later compile to WebAssembly for a static web page.

## Commands
- Build: `cargo build`
- Run: `cargo run` (built-in sample), `cargo run -- web/puzzles/<file>.json` (search for a winning pile), `cargo run -- web/puzzles/<file>.json "Card" "Card" ...` (verify that pile)
- Test all: `cargo test`
- Single test: `cargo test <test_name_substring>` (add `-- --exact` to match a full path like `module::tests::name`)
- Lint: `cargo clippy --all-targets -- -D warnings`
- Format: `cargo fmt` (check only: `cargo fmt --check`)
- Lint the wasm feature too: `cargo clippy --all-targets --features wasm -- -D warnings`
- WebAssembly build: `wasm-pack build --target web --out-dir web/pkg --features wasm` (`--out-dir` must come before `--features`, which wasm-pack forwards to cargo; output in `web/pkg/`, gitignored), then `node wasm/smoke.mjs` to check it and the site's pure modules
- Preview the site: `python3 web/tools/serve.py` (port 8000, sends `Cache-Control: no-store` so edited modules never mix with cached ones; plain `http.server` caused a stuck "Loading…"), then open `http://localhost:8000/?puzzle=cavern-wizard` (without `?puzzle=` it loads today's `web/puzzles/YYYY-MM-DD.json`). Add `&view=phone` to see the phone layout in a 390×844 frame. In the RustRover dev container, open it with `"$BROWSER" "<url>"`, which forwards the port to the host
- Rate a puzzle (tries every pile; use `--release`, it is ~30× faster): `cargo run --release -- rate web/puzzles/<file>.json`
- Survey generated puzzles (table plus the spread of each measure): `cargo run --release -- survey [--count N] [--seed S] [--budget B]`; generate with limits: `cargo run --release -- generate [--count N] [--seed S] [--max-ideas K] [--max-sets K] [--max-share P%] [--min-decoys D] [--order-matters]`. `--count 0` runs until stopped, `--start N` resumes a seed at attempt N; every run skips puzzles already in `puzzles/generated/` or `web/puzzles/` (`generate::fingerprint`: same state, whatever the id, title, solution or listing order), so runs can be stopped and restarted without repeats. Long runs: `nohup setsid nice -n 10 ./target/release/doomdle generate --count 0 > puzzles/generated/generate.log 2>&1 &` from the repo root. Both write to `puzzles/generated/` (gitignored) and take minutes: most dealt states have no winning pile, and proving that means trying every pile
- Schedule daily puzzles: `cargo run --release -- schedule --report` (quick: what the pool in `puzzles/generated/` covers, in weeks per tier), `cargo run --release -- schedule [--from YYYY-MM-DD] [--weeks N | --days N] [--start-with medium,easy,…] [--exclude gen-a,gen-b] [--dry-run]` (`--start-with` sets the first days' tiers before the weekly pattern, `--exclude` skips generated files by name) (assigns pool puzzles to the next free dates following `schedule::WEEK`, re-rating each first, and writes `web/puzzles/<date>.json` with id = date, title "Puzzle #N", its difficulty and solution; dates that already have a file are never touched). Workflow: run the generator, `schedule --report`, `schedule --weeks N`, commit the new dated files, push
- The generator's end-to-end test is `#[ignore]`d because it takes minutes unoptimised: `cargo test --release -- --ignored`
- Router tests: `node site/route.test.mjs`
- Deploy: push to `main`. `.github/workflows/ci.yml` runs fmt, both clippy runs, the tests, the wasm build, the smoke and router tests on every push; on `main`, once the repo secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` exist, it uploads `web/` (minus `tools/` and dev-only `pkg` files) to the Cloudflare Pages project `doomdle` and deploys the router Worker in `site/`
- Card images: `node web/tools/fetch-images.mjs` (needs the wasm build and the network) rewrites `web/card-images.json`; run it when the card pool changes

Before saying a task is done, run fmt, clippy and test and make sure all three pass. Report the test results in your summary.

## Rules source of truth
- `CARDS.md` defines every card in the pool and exactly how it behaves *in this engine*. Read it before touching any card logic.
- Never add a card that isn't in `CARDS.md`. Never change `CARDS.md` yourself; propose the change and I'll make it.
- If a card interaction isn't covered by `CARDS.md` or the scope below, stop and ask. Do not guess Magic rules.

## Scope
- The puzzle starts as Doomsday resolves: the player chooses 5 cards from library + graveyard and orders them.
- One turn only, no combat, no opponent turn.
- The opponent can respond (counterspells, Stifle, etc.) but never acts proactively. See "Decisions" in `CARDS.md` for the exact rules.
- Mana is tracked as simple per-color counts (plus colorless), not a general mana system.

## Architecture
- `Card` is an enum with one variant per card. All card-specific behavior lives in one module (`src/cards.rs`) as `match` arms.
- `State` is a plain data struct deriving `Clone, Debug, PartialEq, Eq, Hash`. It covers both players.
- The engine has a real stack and priority from the start, even while the opponent always passes. Spells and triggers go on the stack; both players get priority before the top item resolves. Do not resolve spells immediately as a shortcut.
- `apply(&State, Action) -> State` is pure: it returns a new state and never mutates its input.
- `legal_actions(&State) -> Vec<Action>` is the only place that decides what's legal, for whichever player has priority or a choice.
- The solver is an AND/OR depth-first search: at your decision points it needs one winning action; at the opponent's it needs every action to still lose for them. It returns your winning strategy if one exists. Memoize visited states.
- No `unwrap()`/`expect()` outside tests; return `Result`/`Option`.
- Keep dependencies minimal. Ask before adding a crate.

## Testing

- Never weaken or delete a failing test to make it pass. Tell me instead.
